| 项目 | 内容 |
| --- | --- |
| 项目名称 | 校园二手物品流转与闲置发布平台 |
| 项目性质 | 大一课程实践 / 新手练手项目 |
| 项目周期 | 2 周（14 天） |

## 二、目标用户与使用场景

- **目标用户**：在校学生（以本科生为主）。
- **典型场景**：
  1. 学长学姐毕业/放假前想处理教材、台灯、球拍等闲置物品；
  2. 新生入学想低价淘到教材、生活用品；
  3. 同学之间在宿舍楼栋内就近完成线下当面交接。

## 三、核心需求

1. **发布闲置**：填写物品名称、分类、价格、成色、描述、联系人与宿舍，即可发布一件闲置。
2. **浏览物品**：首页以卡片网格展示在售闲置，附价格贴纸、分类贴纸与发布信息。
3. **搜索商品**：按关键词匹配物品标题、描述与分类名，实时过滤列表。
4. **查看详情**：点击卡片进入详情页，查看大图、描述、成色、发布人与浏览次数。
5. **管理我的发布**：查看自己发布的闲置，支持删除（需二次确认）。

## 五、明确不做的事（需求边界）

按任务书要求，剔除一切复杂功能，**以下内容本项目不做**：

- ❌ 实名认证、登录注册
- ❌ 在线交易、支付、订单
- ❌ 聊天私信、留言评论
- ❌ 后台审核、管理员系统
- ❌ 服务器部署、数据库、后端开发
- ❌ 复杂算法、性能优化

## 六、非功能需求

1. **零依赖**：仅使用 HTML / CSS / 原生 JavaScript，不引入任何框架。
2. **本地可运行**：无需联网、无需部署，双击 `index.html` 即可运行。
3. **数据模拟**：商品数据内置模拟数据（`data.js`），用户发布数据保存在浏览器 `localStorage`。
4. **基础体验**：适配手机端（底部导航）、键盘焦点可见、支持系统「减少动效」偏好。
5. **安全性基础**：所有用户输入渲染前做 HTML 转义，防止页面错乱与脚本注入。

## 七、验收要点（对应任务书第九条）

1. 流程完整：需求、设计、开发、测试、总结五环节均有文档与产出。
2. 文档齐全：需求说明书、设计文档、测试记录、总结报告格式规范。
3. 分工明确：组长 / 设计文档组 / 开发组职责清晰、全员参与。
